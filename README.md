# Alfa Insight

**Персональная аналитика новостей для бизнеса.** Сервис помогает понять, какие
события могут повлиять на конкретную компанию, какие риски и возможности с ними
связаны и что стоит проверить перед принятием решения.

Пользователь выбирает компанию, получает подходящие ей новости, запускает
AI-анализ события и задаёт уточняющие вопросы в чате. Анализ опирается на профиль
компании, новость и доступные материалы Альфа-Банка; источники можно посмотреть
в интерфейсе.

### Продление API-ключа для проверки

Решение размещено на собственном сервере и использует предоставленный организаторами хакатона API-ключ для обращения к языковой модели.

Согласно условиям организаторов, действие выданных ключей автоматически прекращается после дедлайна хакатона.

Для полноценной проверки размещённого решения необходимо повторно активировать или продлить API-ключ команды ***NEURON*** на период оценки проекта.

## Что умеет проект

- Выбирать компанию из загруженного справочника и показывать её бизнес-контекст:
  отрасль, регион и используемые банковские продукты.
- Формировать персональную ленту новостей с оценкой релевантности компании.
- Объяснять связь события с бизнесом, возможные риски, возможности и действия.
- Подбирать подтверждающие материалы и показывать источники анализа.
- Отвечать на вопросы по выбранному анализу с учётом истории диалога.
- Сохранять новости, результаты анализа и сообщения в PostgreSQL.

## Быстрый запуск из исходников

Самый простой способ запустить весь проект — Docker. На компьютере нужны
**Git и Docker с Compose v2**. Отдельно устанавливать Python, Node.js или
PostgreSQL для этого способа не требуется.

### 1. Подготовьте настройки

Скачайте репозиторий и откройте терминал в его корне — папке, где лежит
`compose.yaml`. Создайте отдельный файл настроек Docker:

```bash
cp .env.docker.example .env.docker
chmod 600 .env.docker
```

Заполните в `.env.docker` следующие значения:

| Переменная | Что указать |
| --- | --- |
| `DOCKERHUB_USERNAME` | Имя пользователя Docker Hub. Для локальной сборки без публикации можно указать `local` — значение нужно для имени образов. |
| `IMAGE_TAG` | Тег версии, например `local`. |
| `POSTGRES_PASSWORD` | Собственный пароль БД. Для текущей конфигурации используйте случайную hex-строку. |
| `LLM_API_KEY` | Действующий ключ API языковой модели. |
| `HTTP_PORT` | Для запуска на компьютере удобно указать `8080`. |
| `HTTP_BIND_ADDRESS` | `127.0.0.1` для доступа только со своего компьютера; `0.0.0.0` для доступа с других устройств. |

Пароль можно сгенерировать командой:

```bash
openssl rand -hex 32
```

Остальные параметры берутся из примера: адреса API модели, модель, имя базы
и пользователь PostgreSQL. При необходимости замените их на параметры своего
провайдера. Для AI-анализа нужен рабочий ключ; значение-заглушка его не заменяет.
`.env.docker` содержит секреты и исключён из Git.

### 2. Соберите и запустите приложение

```bash
docker compose --env-file .env.docker -f compose.yaml -f compose.build.yaml up -d --build --wait --wait-timeout 600
```

Первая сборка скачивает зависимости и может занять значительное время.
После сборки отдельный контейнер подготовит базу, загрузит исходные CSV,
создаст поисковые индексы и попробует получить новости из RSS.

При `HTTP_PORT=8080` откройте **[http://localhost:8080](http://localhost:8080)**.
Нажмите «Попробовать», выберите компанию и роль, откройте новость и нажмите
«Анализировать с ИИ». После анализа можно задавать уточняющие вопросы.

### 3. Проверка и остановка

Посмотреть состояние сервисов и последние сообщения:

```bash
docker compose --env-file .env.docker ps -a
docker compose --env-file .env.docker logs --tail=100 init backend frontend
```

Контейнер `init` должен завершиться с кодом `0`: это одноразовая подготовка,
а не постоянно работающий сервис.

Остановить приложение:

```bash
docker compose --env-file .env.docker down
```

Данные останутся в Docker-томе PostgreSQL. **Не добавляйте `-v`, если хотите
сохранить базу:** эта опция удаляет том вместе с данными.

## Запуск на сервере

Для сервера предусмотрен запуск готовых образов из Docker Hub. После их
публикации на сервер достаточно перенести `compose.yaml` и заполненный файл
настроек под именем `.env`, затем выполнить:

```bash
docker compose up -d --wait --wait-timeout 600
```

При `HTTP_PORT=80` и `HTTP_BIND_ADDRESS=0.0.0.0` сайт будет доступен по внешнему
IP сервера, если порт открыт в сетевых правилах.

**Подробная инструкция по сборке и публикации образов, подготовке Ubuntu,
развёртыванию, обновлению и резервному копированию — в [DEPLOY.md](DEPLOY.md).**
В репозитории также есть [скрипт установки Docker на Ubuntu](install-docker-ubuntu.sh).

## Как работает сервис

### 1. Профиль компании

Исходные CSV из `data/raw/` импортируются в PostgreSQL. Они содержат сведения
о компаниях, платежах и связях физических лиц с компаниями. Backend собирает
профиль: отрасль, регион, признаки банковских продуктов и другие доступные
характеристики. Для модели формируется компактная выжимка; исходный массив
платежей целиком в модель не отправляется.

### 2. Персональная лента

Новости загружаются из RSS и сохраняются в базе. Для выбранной компании сервис
подбирает кандидатов и оценивает связь события с её деятельностью. Лента сначала
может вернуть предварительный локальный подбор; уточнение с помощью модели
выполняется в фоне и кешируется. Уточнённые оценки доступны при следующем запросе
ленты — текущий интерфейс не опрашивает готовность автоматически.

### 3. Анализ новости

AI-агент выполняет последовательность шагов, описанную через **LangGraph**:

1. Загружает профиль компании и выбранную новость.
2. Оценивает, как событие связано с бизнесом, и составляет план поиска.
3. Ищет подходящие выдержки из банковской аналитики и связанные материалы.
4. Формирует объяснение, условные риски, возможности и предлагаемые действия.
5. Проверяет структуру ответа, ссылки на источники и подтверждение выводов.
6. Сохраняет результат и запись выполненных этапов.

Для поиска используется подход **RAG**: перед формированием ответа модель
получает найденные материалы из подготовленного корпуса. В основном Docker-запуске
поиск работает через **PostgreSQL Full-Text Search (FTS)** — без отдельной
векторной базы и скачивания embedding-модели.

Рабочий корпус содержит проверенные выдержки из аналитических документов
Альфа-Банка с датами и номерами страниц. Его состав описан
в [документации корпуса](backend/app/rag/data/REVIEWED_CORPUS.md).
Если подходящей позиции банка нет, сервис отмечает это и отделяет
AI-интерпретацию от подтверждённых банковских материалов.

### 4. Уточняющий чат

Чат связан с конкретным сохранённым анализом. Он использует контекст компании,
новости, источников и предыдущих сообщений. История сохраняется в PostgreSQL,
поэтому перезапуск контейнеров с сохранённым томом не удаляет переписку и анализы.

## Архитектура

```text
Браузер
   │
   ▼
Nginx + React
   │ /api/*
   ▼
FastAPI ───────────────► API языковой модели
   │                    генерация и оценка релевантности
   ├── Данные компаний и новости
   ├── AI-агент на LangGraph
   └── Поиск материалов через RAG / FTS
   │
   ▼
PostgreSQL
профили, платежи, новости, поисковые индексы, анализы, чат
```

| Часть | Технологии и назначение |
| --- | --- |
| Интерфейс | React, TypeScript, Vite, React Router, SCSS, Motion. Выбор компании, лента, анализ и чат. |
| Backend | Python, FastAPI, SQLAlchemy и psycopg. API и работа с данными. |
| AI-агент | LangGraph, Pydantic, асинхронный LLM-клиент с резервным API-адресом. |
| Поиск | PostgreSQL FTS в основном запуске; дополнительные режимы поиска реализованы в модуле RAG. |
| Хранилище | PostgreSQL 16 и постоянный Docker-том. |
| Развёртывание | Docker Compose; Nginx отдаёт интерфейс и направляет API-запросы в backend. |

В Compose четыре сервиса: `postgres`, одноразовый `init`, `backend` и `frontend`.
Наружу публикуется порт frontend; база и backend доступны внутри Docker-сети.

## Основные API

| Метод и путь | Назначение |
| --- | --- |
| `GET /api/companies` | Список и поиск компаний. |
| `GET /api/companies/{company_id}` | Профиль выбранной компании. |
| `GET /api/news?company_id=...` | Персональная лента. |
| `GET /api/news/{news_id}` | Содержимое новости. |
| `POST /api/insights/analyze` | Создать анализ по `company_id` и `news_id`. |
| `GET /api/insights/{insight_id}` | Получить сохранённый анализ. |
| `POST /api/insights/{insight_id}/ask` | Задать вопрос по анализу. |
| `GET /api/insights/{insight_id}/messages` | Получить сохранённые сообщения. |
| `GET /api/insights/{insight_id}/trace` | Получить запись этапов анализа. |

Backend запускается через фабрику `app.agent.api:create_app`: она объединяет
API компаний, персональную ленту, анализ и чат в одном приложении.

## Обновление новостей

При первом запуске сервис пробует получить RSS, если таблица новостей пуста
и включён `FETCH_NEWS_ON_INIT=true`. Периодическая загрузка не настроена.
Чтобы получить новые публикации и обновить их поисковый индекс вручную:

```bash
docker compose --env-file .env.docker exec backend python backend/scripts/fetch_news.py
docker compose --env-file .env.docker exec backend python -m app.rag.cli index-db-news --store fts
```

На сервере с файлом `.env` параметр `--env-file .env.docker` нужно опустить.

## Ограничения текущей версии

- Полнота ленты зависит от доступности RSS и ограниченного набора кандидатов.
  В базе может храниться краткое описание вместо полного текста публикации.
- Корпус банковской аналитики — подготовленная выборка, а не все документы банка.
  Отсутствие подходящего материала явно отмечается в анализе.
- AI-выводы о последствиях условны. Они не являются подтверждённой позицией банка
  и требуют проверки перед бизнес-решением.
- Анализ зависит от доступности внешнего LLM API и действующего ключа.
- Часть пунктов бокового меню — элементы демонстрационного интерфейса;
  отдельные разделы пока не реализованы. Чат работает внутри панели анализа.
- Текущий Docker-запуск рассчитан на один сервер. Авторизация пользователей,
  домен и HTTPS этой конфигурацией не настраиваются.
