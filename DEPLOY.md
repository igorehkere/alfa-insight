# Запуск Alfa Insight через Docker Hub

Одна машина (ПК или ВМ VK Cloud), один экземпляр приложения. Frontend работает
в Nginx, backend — в FastAPI/Uvicorn, база — в PostgreSQL 16. Сервис `init`
подготавливает данные и завершается. Kubernetes и балансировщик не нужны.

## Что добавлено

| Файл | Назначение |
| --- | --- |
| `compose.yaml` | Запуск готовых образов из Docker Hub |
| `compose.build.yaml` | Дополнение для сборки образов на вашем ПК |
| `backend/Dockerfile` | Backend и исходные CSV, без `.env` и локальных окружений |
| `frontend/Dockerfile` | Сборка React и раздача через Nginx |
| `frontend/nginx.conf` | Маршруты React и проксирование `/api/` в backend |
| `backend/scripts/bootstrap.py` | Подготовка БД и поисковых индексов |
| `.env.docker.example` | Настройки развёртывания без настоящих секретов |

Структура приложения и прежние способы разработки сохранены. Docker-сборка
использует текущие исходники, включая локальные изменения в них.

## 1. Подготовить Docker Hub и настройки на ПК

Создайте в своём Docker Hub два репозитория:

- `<username>/alfa-insight-backend`
- `<username>/alfa-insight-frontend`

Backend-образ содержит `data/raw` для первого наполнения БД. Используйте private
репозиторий, если эти CSV не должны быть публичными. Пароли и API-ключи в образ
не копируются и через параметры сборки не передаются.

В корне проекта:

```bash
cp .env.docker.example .env.docker
chmod 600 .env.docker
openssl rand -hex 32
```

Отредактируйте `.env.docker`:

- `DOCKERHUB_USERNAME` — ваше имя в Docker Hub, строчными буквами;
- `IMAGE_TAG` — новый тег версии, например `2026-10-25-1`;
- `POSTGRES_PASSWORD` — сгенерированная hex-строка;
- `LLM_API_KEY` — действующий ключ LLM.

Остальные настройки можно оставить по примеру. Не используйте значения
`replace_with_...`. Имя БД и пользователя оставьте стандартными либо используйте
простые имена из букв, цифр и подчёркиваний. Пароль включается в URL подключения,
поэтому здесь используется hex-строка без символов, требующих URL-кодирования.

`.env.docker` находится в `.gitignore`. Текущий `.env` для локальной разработки
можно сохранить: все команды сборки ниже явно используют `.env.docker`.
Не экспортируйте в оболочке другие значения переменных с теми же именами:
переменные оболочки имеют приоритет над `--env-file`.

## 2. Собрать и опубликовать образы с ПК

Установите Docker Engine с Compose v2, либо Docker Desktop. Официальная инструкция
для Ubuntu: [Install Docker Engine](https://docs.docker.com/engine/install/ubuntu/). Команды ниже предполагают,
что текущий пользователь имеет доступ к Docker; иначе используйте `sudo` последовательно.

```bash
docker login
docker compose --env-file .env.docker -f compose.yaml -f compose.build.yaml config --quiet
docker compose --env-file .env.docker -f compose.yaml -f compose.build.yaml build backend frontend
docker compose --env-file .env.docker -f compose.yaml -f compose.build.yaml push backend frontend
```

Backend и `init` используют один образ; публиковать его дважды не нужно.
Первая сборка требует интернета и может занять время: проект сохраняет существующие
Python-зависимости, в том числе CPU PyTorch. Для FTS скачивание embedding-модели не требуется.

Собирайте на ПК Linux/amd64 или Docker Desktop с архитектурой образов amd64,
если ВМ имеет архитектуру x86_64. При сборке на ARM для такой ВМ используйте:

```bash
DOCKER_DEFAULT_PLATFORM=linux/amd64 docker compose --env-file .env.docker -f compose.yaml -f compose.build.yaml build backend frontend
```

Для проверки на своём ПК после сборки задайте `HTTP_PORT=8080` в `.env.docker`
и выполните:

```bash
docker compose --env-file .env.docker up -d --wait --wait-timeout 600
```

Откройте `http://localhost:8080`. На ПК и на ВМ будут независимые базы данных.
Compose хранит их в локальном томе `alfa-insight_postgres_data`.

Собрать и запустить из исходников на ПК можно и одной командой:

```bash
docker compose --env-file .env.docker -f compose.yaml -f compose.build.yaml up -d --build --wait --wait-timeout 600
```

## 3. Создать ВМ в VK Cloud

Создайте обычную ВМ с Ubuntu 24.04 LTS x86_64, SSH-ключом и внешним IP.
Для начала можно заложить 4 vCPU, 8 ГБ RAM и 60 ГБ диска: это оценка запаса
для текущих зависимостей и образов, а не результат нагрузочного тестирования.
После первого запуска ориентируйтесь на фактическое потребление.

Настройте сетевой доступ:

- TCP 22 — SSH с вашего IP;
- TCP 80 — доступ к приложению с нужных адресов;
- исходящий доступ к Docker Hub, источникам RSS и HTTPS API LLM.

Порты 5432 и 8000 в Compose не публикуются. Первоначальный запуск использует HTTP
по IP. Домен и HTTPS можно добавить отдельно; текущая конфигурация их не настраивает.
У приложения нет добавленной этим развёртыванием авторизации: для закрытой демонстрации
ограничьте доступ к TCP 80 нужными IP в правилах сети.

Установите Docker по официальной инструкции для Ubuntu выше. Проверьте:

Либо перенесите на ВМ файл `install-docker-ubuntu.sh` из корня проекта
и выполните `sudo sh install-docker-ubuntu.sh`. Он использует официальный
репозиторий Docker для Ubuntu и устанавливает также Compose.

```bash
docker version
docker compose version
```

Включите запуск Docker при загрузке ВМ:

```bash
sudo systemctl enable --now docker
```

## 4. Перенести на ВМ только конфигурацию

В домашнем каталоге пользователя ВМ создайте папку:

```bash
mkdir -p ~/alfa-insight
```

С ПК перенесите в неё `compose.yaml` и `.env.docker`, переименовав последний
в `.env`. В примере замените `USER`, `VM_IP` и при необходимости укажите SSH-ключ:

```bash
scp compose.yaml USER@VM_IP:~/alfa-insight/compose.yaml
scp .env.docker USER@VM_IP:~/alfa-insight/.env
```

На ВМ:

```bash
cd ~/alfa-insight
chmod 600 .env
```

Проверьте в `.env` имя Docker Hub, тег образов, пароль и ключ. Для доступа по
`http://VM_IP` задайте `HTTP_PORT=80` и `HTTP_BIND_ADDRESS=0.0.0.0`.
На ВМ исходники, CSV, Node.js, Python и `compose.build.yaml` не нужны.

Для private-образов выполните `docker login` под тем пользователем, от которого
будете запускать Compose. Для ВМ можно использовать Docker Hub token с правом чтения.

## 5. Запустить одной командой

Из папки с `compose.yaml` и `.env`:

```bash
docker compose up -d --wait --wait-timeout 600
```

При первом запуске Compose скачает образы. Время загрузки зависит от сети.
Затем выполняются следующие шаги:

1. PostgreSQL запускается и проходит проверку готовности.
2. `init` создаёт таблицы, загружает CSV в пустую БД и подготавливает FTS-поиск.
3. Если новостей нет и `FETCH_NEWS_ON_INIT=true`, выполняется попытка загрузки RSS.
   Недоступность RSS не блокирует запуск; остальные ошибки инициализации блокируют backend.
4. Backend запускается и проходит `/health`, включая обращение к БД.
5. Nginx начинает отдавать интерфейс и проксировать API.

Откройте `http://VM_IP`. Успешное завершение `init` с кодом 0 — нормальное состояние,
этот контейнер не должен работать постоянно. Проверка готовности не вызывает платный
LLM-запрос: работу анализа с вашим ключом проверяйте отдельно в интерфейсе.

```bash
docker compose ps -a
docker compose logs --tail=100 init backend frontend
curl --fail http://localhost/api/companies?limit=1
```

Проверьте отображение компаний, новостей и выполнение анализа. Если RSS были
недоступны, загрузите новости и обновите индекс позже:

```bash
docker compose exec backend python backend/scripts/fetch_news.py
docker compose exec backend python -m app.rag.cli index-db-news --store fts
```

Периодическая загрузка новостей этой конфигурацией не запускается: команды выше
можно выполнять вручную. Текущий индексатор обрабатывает до 200 последних новостей,
как и существующий способ локального запуска.

## 6. Обновление и остановка

Для новой версии задайте новый `IMAGE_TAG` на ПК, соберите и опубликуйте образы
командами из шага 2. На ВМ сохраните резервную копию БД, затем задайте этот же тег в `.env`:

```bash
docker compose exec -T postgres sh -c 'pg_dump -U "$POSTGRES_USER" -d "$POSTGRES_DB" -Fc' > backup.dump
docker compose pull
docker compose up -d --wait --wait-timeout 600
```

`init` повторно создаёт недостающие таблицы и обновляет банковский индекс из новой
версии образа. Заполненные таблицы компаний повторно не импортируются; история
анализа и чаты сохраняются. Новая версия CSV в образе автоматически не заменяет
уже загруженные данные. Несовместимые изменения схемы требуют отдельной миграции.

При обычной остановке:

```bash
docker compose down
```

Том БД остаётся на машине. `docker compose down -v` удалит его вместе с данными.
Не используйте эту опцию для обычного обновления или остановки.
`restart: unless-stopped` возвращает основные сервисы после перезапуска Docker/ВМ,
если вы не остановили их вручную. Это один сервер, без отказоустойчивости.

Если запуск завершился ошибкой, сначала посмотрите `docker compose ps -a` и логи.
После исправления конфигурации повторите команду запуска. Если требуется повторить
подготовку БД при неизменном образе, выполните `docker compose run --rm init`,
а затем команду запуска. Пароль уже созданной БД не меняется от редактирования
`POSTGRES_PASSWORD` в `.env`: смена пароля существующего пользователя выполняется
отдельно внутри PostgreSQL.

## Проверки перед передачей

Локально проверены сборки обоих Docker-образов, запуск через Compose,
подготовка чистой PostgreSQL 16 (85 514 компаний и 1 380 585 платежей),
FTS-поиск, раздача React-маршрутов и API компаний/новостей через Nginx.
Повторная инициализация и пересоздание контейнеров сохранили тестовые
новости, анализы и сообщения чата. Проверена остановка автоимпорта при
неполной базе без перезаписи платежей. Тестовое окружение отделено от
локальных рабочих баз.

Публикация в ваш Docker Hub и запуск в VK Cloud выполняются по шагам выше.
LLM-запрос с вашим настоящим ключом в эти проверки не входил.
