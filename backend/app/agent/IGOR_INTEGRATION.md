# Игорю: как подключить часть Димы

Агент и RAG подключаются к твоему единому FastAPI. Отдельный сервер не нужен.
Я менял только `app/agent` и `app/rag`. Твой `main`, news, компании и frontend не менял.

## 1. Подключение в твоём main

После создания `app` и подключения твоих роутеров добавь:

```python
from app.agent.integration import install_agent

install_agent(app)
```

Это подключает анализ, чат, trace, восстановление результата/истории и
персональную ленту `GET /api/news?company_id=...`. Твои catalog, детали новости,
компании, middleware и lifespan сохраняются. Клиент LLM закрывается при остановке.
Запускай свой обычный `app.main:app`.

Если персональная лента у тебя уже есть, используй
`install_agent(app, include_feed=False)`. При занятом URL установка выдаст понятную
ошибку. Роутеры с одинаковыми URL одновременно не подключаем.

Адаптер по умолчанию использует существующие `SessionLocal`, `Company`, `News`
и функции `company_profile`/`counterparties` из `app.main`. Импорты этих функций
происходят только при запросе, после загрузки main.

## 2. Настройка и подготовка БД — один раз до запуска

Из корня `alfa-insight`, с активированным окружением проекта:

```bash
source .venv/bin/activate
export PYTHONPATH=backend
```

Зависимости MVP перечислены в `backend/app/agent/requirements-mvp.txt`.
Это дополнение для сборки общего backend; общий `requirements.txt` я не менял.

В корневом `.env` нужны `DATABASE_URL`, `LLM_BASE_URL`, `LLM_API_KEY`, `LLM_MODEL`.
Для основного варианта задай `RAG_SEARCH_MODE=fts`. `RAG_DATABASE_URL` можно
не задавать: тогда RAG использует ту же БД, что и backend. Переменные окружения
имеют приоритет над `.env`. Ключ остаётся только на сервере.

```bash
python -m app.agent.persistence init-db
python -m app.rag.cli init-db --store fts
python -m app.rag.cli index-bank --store fts --input backend/app/rag/data/reviewed_corpus.json
python -m app.rag.cli search --store fts --query "ключевая ставка" --as-of 2026-10-24
```

Создаются только `dima_agent_insights`, `dima_agent_chat_messages` и
`dima_rag_fts_*`. Существующие `insights`, `chat_messages`, компании и новости
не меняются. Старые анализы из прототипных таблиц автоматически не переносятся.
Если собственная таблица агента имеет другую схему, команда остановится до создания
остальных таблиц. `create_all` не выдаётся за миграцию существующей схемы.

FTS использует обычную PostgreSQL, без pgvector, E5 и загрузки моделей.
Существующий гибридный поиск сохранён: для него отдельно нужны
`RAG_SEARCH_MODE=hybrid`, pgvector, локальная E5 и импорт с `--store postgres`.
Оба режима требуют собственного явного импорта индекса. Автоматического импорта
при запуске backend нет.

В `reviewed_corpus.json` — 10 сверенных выдержек из 3 предоставленных PDF,
с датами и физическими страницами. Это выбранные выдержки, а не полный OCR всех PDF.
Как расширить корпус — в `app/rag/data/REVIEWED_CORPUS.md`.

## 3. Что вызывать с frontend

| Действие | Запрос |
|---|---|
| Персональная лента | `GET /api/news?company_id=U_25835&limit=10` |
| Анализ | `POST /api/insights/analyze` |
| Вопрос | `POST /api/insights/{insight_id}/ask` |
| Шаги агента | `GET /api/insights/{insight_id}/trace` |
| Сохранённый анализ | `GET /api/insights/{insight_id}` |
| История чата | `GET /api/insights/{insight_id}/messages` |

Тело анализа: `{"company_id":"U_25835","news_id":"2","force_refresh":false}`.
Здесь `2` нужно заменить реальным ID новости из твоего API.
Тело вопроса: `{"question":"Что стоит проверить нашей компании?"}`.
ID агента — строки; числовой ID новости из твоего API переводи через `String(id)`.
Схемы анализа/чата — `app/agent/schema.py`.

Анализ возвращает `insight_id`, `result`, `agent_trace`, ID компании/новости и статус.
Сохраняй `insight_id` для вопросов и восстановления. Контекст и usage остаются на
сервере. Повторный анализ берётся из кеша; `force_refresh=true` создаёт новый ID
с отдельной историей. При смене компании очищай выбранный анализ в интерфейсе.

Показывай `warnings`. `bank_position.status=not_found` — нормальный результат.
URL банковского источника может быть `null`; показывай название и `page_number`.
В чате больше нет сброса после третьего вопроса. Читаются до 12 последних обменов
и необязательное состояние задачи; в модель уходят три компактных обмена и активные
пользовательские условия. Старые репозитории с двумя обменами совместимы, но имеют
меньше доступной памяти. Полная история сохраняется.
Ошибка анализа при отказе LLM — 503. Чат по сохранённому анализу в этом случае
может вернуть 200 с общими рекомендациями и явным предупреждением.
404 — объект отсутствует, 409 — неоднозначность/конфликт, 422 — плохой ввод или
неподтверждённый ответ, 503 — недоступность LLM/БД/RAG или таймаут.
Максимальная длина вопроса — 2000 символов.

Твои catalog/детали остаются в твоём формате (`source_name`, `content` и т. д.).
Персональная лента возвращает `source`, строковый `id`, теги и причины релевантности.
Она работает без RAG. При доступной LLM агент формирует компактное отраслевое
описание компании и оценивает новости пакетами; профиль и оценки переиспользуются
в памяти runtime. Без LLM остаётся консервативный локальный подбор.
Не используй общий catalog вместо этой ленты.

Контракт подключения не изменился. Дополнительные поля карточки:
`relevance_level` (`high`/`medium`/`low`), `relevance_method` (`llm`/`local`),
`event_analysis` (событие, адресаты, выдержка, механизм влияния, поля и условия;
`null` при локальной оценке). Прежние `relevance_score` и `relevance_reasons` сохранены.
Модельные оценки: 80/15/5 соответственно, чтобы существующий порог высокой оценки
20 не превращал условные связи в высокие. Локальные оценки не выше 15.
Отображение трёх отдельных названий уровней требует поддержки frontend;
агент не меняет интерфейс. Лимиты и кеш описаны в README агента.

Лента отвечает без ожидания LLM: используются кешированные оценки и предварительный
локальный подбор. Недостающие оценки готовит фоновая задача `AgentRuntime`.
Необязательный `ranking_status` (`ready`/`refreshing`/`partial`) позволяет интерфейсу
позже добавить повторное получение результата. Пока уточнённые оценки видны при
следующем запросе ленты, автоматическое обновление frontend агент не добавляет.

## 4. Если хочешь сам реализовать HTTP и хранение по плану

Вызывай `await run_analysis(company_id, news_id, tools)` из `app.agent.service`.
В `run.analysis` — публичные `result` и `agent_trace`, в `run.context` — закрытые
доказательства для чата, в `run.usage` — метрики. Сохраняй все три отдельно.
Публичный ответ собирается через `InsightResponse` с назначенным тобой ID.

Вопрос: `await answer_question(saved, question, tools, history=last_two,
turn_count=total)`. `saved` содержит публичный анализ и `context`.
`tools` создаются через `ServiceTools`/`HybridServiceTools` с твоими async-загрузчиками;
готовый `AgentRuntime` умеет это делать через синхронный repository.
Для собственного repository передай `install_agent(app, repository=your_repository)`;
его методы и сигнатуры показаны в `persistence.py`. Каждая SQL-операция открывает
свою сессию. Если переносишь функции профиля из main, адаптируй эти загрузчики.

## Ограничения и проверка

Для текущего кеша и очереди используй один worker: lock действует внутри процесса.
Лимит ожидания анализа по умолчанию 90 секунд включает очередь и подготовку RAG;
таймаут не останавливает уже выполняющуюся синхронную SQL-операцию в потоке.
Не повторяй POST автоматически после сетевого таймаута. Для нескольких worker
нужна общая блокировка/идемпотентность в твоём repository.
Количество шагов и токены ограничены; рублёвую квоту общего ключа контролирует
провайдер. Без подтверждённого тарифа usage не переводится в рубли.

Проверки без платных вызовов:

```bash
python -m unittest discover -s backend/app/agent/tests -v
python -m unittest app.rag.tests.test_fts -v
```

Для SQL-проверок нужен `DIMA_TEST_FTS_DATABASE_URL`, указывающий строго на отдельную
одноразовую БД `dima_rag_test`; иначе они пропускаются. Полный набор `app/rag/tests`
также проверяет hybrid и требует его необязательные зависимости.

Проверены HTTP-сценарий, кеш, чат, trace, ошибки, FTS и хранение в отдельной
PostgreSQL на синтетических компаниях/новостях. Живой вызов LLM в этой доработке
не запускался: требуется разрешение владельца ключа на отправку выдержки и расход квоты.
